# mobile-guide.md 작성 가이드

`mobile-guide.md`를 새로 만들 때 이 구조를 뼈대로 쓴다. 프로젝트에 해당 없는 절은 빼고, 필요한
절은 자유롭게 추가한다 — 아래는 빠뜨리기 쉬운 항목을 놓치지 않기 위한 체크리스트지, 고정 양식이
아니다. **값은 실제로 실행해서 확인한 것만 적는다** — `package.json`, `app.json`, 실행 로그를 직접
열어보고 확인한 값을 옮긴다. 이상적인 값이나 아직 겪지 않은 문제를 추측해서 채우지 않는다.

## 예시 구조

```md
# <앱 이름> 모바일 개발 가이드

## 프로젝트 개요
- 프레임워크: Expo SDK 57 (React Native 0.86), 라우팅: expo-router
- 패키지 매니저: Bun (isolated linker)
- 스타일링: NativeWind v4 + Tailwind
- 백엔드: <API 서버 이름>, 로컬 포트 6100
- 모노레포 내 위치: apps/<앱 폴더>

## 로컬 실행 방법
1. 백엔드 API 서버 먼저 기동: `cd apps/<api> && bun run dev` (포트 6100)
2. Metro 기동: `cd apps/<app> && npx expo start`
3. iOS 시뮬레이터: `npx expo run:ios` (최초 1회, 이후는 Metro만 재시작하면 됨)
4. Android 에뮬레이터: `JAVA_HOME=/opt/homebrew/opt/openjdk@17 npx expo run:android`
   (이 머신은 기본 JDK가 25라 Android 빌드에만 17을 지정해야 함 — 3절 참고)

## 알려진 환경 이슈와 해결법
(실제로 겪은 것만 여기 쌓는다 — 아래는 "이런 식으로 적으라"는 예시 항목)

### 스타일이 컴파일은 되는데 화면에 반영 안 됨 (2026-09-23)
- **원인**: `react-native-css-interop`이 앱 package.json에 직접 의존성으로 없어서, babel이 생성한
  bare import가 모노레포 루트의 잔재 사본으로 resolve됨 — 실제 nativewind가 쓰는 사본과 다른 물리
  파일이라 컴파일 결과가 반영 안 됐다.
- **해결**: `react-native-css-interop`을 앱 package.json에 nativewind와 같은 버전으로 직접 추가 후
  `bun install`. 루트의 잔재 사본은 삭제(gitignore 대상이라 안전).
- **왜 기록하나**: 다음에 "스타일이 컴파일은 되는데 안 보인다"는 증상을 다시 보면, 이 항목부터
  확인하면 몇 시간의 디버깅을 아낄 수 있다.

### iPad에서 반응형 2-컬럼 레이아웃이 항상 1열로만 나옴 (2026-09-23)
- **원인**: `app.json`에 `ios.supportsTablet`이 없어서 iPad에서 iPhone 호환성 모드(좁은 창)로 실행됨.
- **해결**: `app.json`에 `"ios": {"supportsTablet": true}` 추가 + 이미 생성된 `ios/` 프로젝트의
  `project.pbxproj`에서 `TARGETED_DEVICE_FAMILY`를 `"1,2"`로 직접 수정(또는 `expo prebuild --clean`).
- **왜 기록하나**: 반응형 로직 자체를 고치려 들면 시간 낭비 — 네이티브 설정 문제였다.

## 디버깅 방법론
- 스타일/설정이 "격리된 최소 재현 프로젝트에서는 되는데 이 모노레포에서는 안 된다"는 패턴이면,
  모노레포 밖에 `bunx create-expo` 등으로 최소 재현을 만들어 비교한다 — 범위를 좁히는 가장 빠른 방법.
- node_modules 안 파일을 열어 진단 코드를 심을 때는 Metro `--clear` 재시작 필수(캐시 때문에 반영
  안 될 수 있음).

## 테스트 계정 / 시드 데이터
- (실제로 있는 테스트 계정 정보나, 없다면 "아직 준비 안 됨"이라고 명시 — 다음 세션이 헛되이 찾지
  않도록)

## 이 환경에서 확인 못 한 것
- (예: "headless 시뮬레이터라 실제 탭/폼 입력 조작 테스트는 못 했음 — GUI 환경에서 재확인 필요")
```

## 작성 시 주의

- **실제로 겪고 해결한 문제만 적는다** — 스킬 사용 중 새 이슈를 만나 해결할 때마다 그 자리에서
  추가한다. 작업을 몰아서 정리하며 기억에 의존해 채우지 않는다.
- **버전 정보를 같이 적는다** — Expo SDK/RN/패키지 버전이 바뀌면 이슈 자체가 사라지거나 다른 증상으로
  바뀔 수 있다. 어느 버전 기준의 기록인지 알아야 다음 사람이 "아직도 유효한가"를 판단할 수 있다.
- **해결법은 재현 가능한 정확한 명령/설정값으로 적는다** — "JDK를 바꿔야 함" 같은 두루뭉술한 서술이
  아니라 실제로 실행한 명령 전체를 옮긴다.
- 오래돼서 더 이상 안 맞는 항목을 발견하면(패키지 업그레이드로 해결됐다든지) 재확인하고 갱신하거나
  제거한다 — 틀린 기록은 없는 것보다 나쁘다.
