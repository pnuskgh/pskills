# Create AGENTS.md — 프로젝트 지침 문서 작성기

코드베이스를 분석해 `AGENTS.md`(프로젝트 전체 지침) 또는 `AGENTS-{name}.md`(특정 에이전트 전용 지침)를 현재 작업 디렉터리에 작성한다. `AGENTS.md`는 CLAUDE.md의 후신 이름이다 — 여러 코딩 에이전트 도구가 공통으로 읽는 파일명으로 자리잡으면서 이름이 바뀌었을 뿐, 목적(프로젝트를 처음 보는 에이전트가 알아야 할 것)은 같다.

## 워크플로우

### 1. 트리거 판별

- **`AGENTS.md`**: 이 디렉터리에서 작업하는 모든 에이전트에게 적용되는 일반 지침.
- **`AGENTS-{name}.md`**: `{name}` 에이전트 한 명에게만 적용되는 범위가 좁은 지침(예: `AGENTS-영업.md`). 프로젝트 전체를 다시 설명하지 않고, 그 역할이 실제로 필요로 하는 부분만 담는다.

### 2. 기존 파일 확인

- 대상 경로(`./AGENTS.md` 또는 `./AGENTS-{name}.md`)에 파일이 이미 있으면 전체 덮어쓰기 대신 기존 내용을 읽고 무엇을 갱신할지 사용자와 확인한다.
- **기존 `CLAUDE.md`의 내용을 마이그레이션하거나 다시 쓰지 않는다.** 요청받은 AGENTS 파일만 새로 쓴다. (CLAUDE.md 연결은 6단계에서 별도로 다룬다 — "손대지 않는다"가 "참조 한 줄도 안 건드린다"는 뜻은 아니다.)

### 3. (AGENTS-{name}.md인 경우) 역할 파악

1. `.claude/agents/{name}.md`가 있으면 Read해서 그 에이전트의 핵심 역할·작업 원칙을 파악한다 (`create-agent`로 채용된 에이전트라면 존재한다).
2. 없으면 `{name}`이 어떤 역할인지, 무엇을 알아야 하는지 사용자에게 먼저 묻는다 — 추측해서 채우지 않는다.
3. 이 역할과 무관한 내용(예: 영업 에이전트에게 배포 파이프라인 세부사항)은 4단계에서 제외한다.

### 4. 코드베이스 분석

실제로 코드를 읽고 확인한다 — 짐작으로 채우지 않는다. 다음 표준 구조를 따른다(6개 섹션):

| 섹션                           | 채우는 근거                                   |
| ---------------------------- | ---------------------------------------- |
| **Project overview**         | 2~3줄. README, package.json description 등에서 실제로 확인한 것 |
| **Build and test commands**  | `package.json`의 scripts, `Makefile`, README의 명령어 등 실제로 존재하는 것만 |
| **Code style guidelines**    | 린터/포매터 설정 파일(biome.json, .eslintrc 등), tsconfig의 strict 옵션 등 코드에서 관찰되는 것만 |
| **Testing instructions**     | 실제 테스트 러너와 실행 명령. 없으면 "테스트 없음"이라고 명시하지, 지어내지 않는다 |
| **PR instructions**          | `git log`에서 실제로 관찰되는 커밋 메시지 컨벤션. 강제되지 않는 느슨한 패턴이면 그렇다고 적는다 |
| **Security and Constraints** | `.gitignore`, 기존 문서에서 실제로 확인되는 금지사항(민감 파일, 브랜치 보호 등) — 일반론 넣지 않음 |

- **주의사항**: 흔히 실수하는 지점(예: 특정 스크립트를 잘못된 런타임으로 실행하면 조용히 깨지는 경우)이 기존 문서/커밋 이력에서 발견되면 별도 섹션이나 해당 섹션 안에 추가한다.
- 모노레포면 하위 폴더마다 자체 `CLAUDE.md`/`AGENTS.md`가 있을 수 있다 — 그런 폴더가 있으면 "이 폴더 안에서는 그 파일이 우선한다"고 한 줄로 밝힌다(직접 요약해서 옮겨적지 않는다 — 중복은 드리프트를 만든다).

`AGENTS-{name}.md`는 위 6개 섹션 중 3단계에서 파악한 역할과 관련된 항목만 선별한다.

### 5. 작성

- 현재 작업 디렉터리에 `AGENTS.md` 또는 `AGENTS-{name}.md`를 만든다 — 다른 위치로 옮기지 않는다.
- **명령형으로, 그리고 실제로 확인된 내용만** 적는다. "아마 ~일 것이다" 같은 추측을 문서에 넣지 않는다 — 지침 파일은 이후 모든 세션이 사실로 받아들인다.
- 이미 알려진 일반 지식(예: "git commit 전에 diff를 확인하라")은 넣지 않는다 — 이 프로젝트에서만 참인 것 위주로 작성한다.

### 6. CLAUDE.md 연결

**Claude Code는 AGENTS.md를 자동으로 읽지 않는다** — CLAUDE.md만 읽는다. AGENTS.md를 써도 연결하지 않으면 이 세션 이후로 아무도 그 내용을 보지 않는다. 같은 디렉터리에:

- **CLAUDE.md가 없으면**: `@AGENTS.md` 한 줄만 담은 최소 CLAUDE.md를 만들지, 심볼릭 링크(`ln -s`)로 대체할지 사용자에게 확인한다. (심볼릭 링크는 git에서 추적/이식성 이슈가 생길 수 있어 기본은 `@AGENTS.md` 참조 방식을 권장.)
- **CLAUDE.md가 이미 있으면**: 그 내용을 재작성하지 않는다 — 안에 `@AGENTS.md` 참조가 없으면 추가해도 되는지만 사용자에게 확인하고, 있으면 그대로 둔다.
- `AGENTS-{name}.md`처럼 이름이 붙은 변형은 파일명이 정확히 `AGENTS.md`가 아니므로 `@AGENTS.md` 자동 참조 대상이 아니다 — 필요하면 `@AGENTS-{name}.md`로 명시적으로 참조해야 한다는 점을 사용자에게 알린다.

### 7. 검증 및 보고

1. 작성한 파일의 명령/경로를 실제로 실행 가능한지 재확인한다(예: 적어 넣은 빌드 명령이 실제 `package.json`에 있는지).
2. 사용자에게 생성/수정된 파일 경로, CLAUDE.md 연결 여부, 핵심 내용을 요약 보고한다.
