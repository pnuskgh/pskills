# ux-design-guide.md 작성 가이드

`ux-design-guide.md`를 새로 만들 때 이 구조를 뼈대로 쓴다. 프로젝트에 해당 없는 섹션은 빼고, 필요한
섹션은 자유롭게 추가한다 — 고정 양식이 아니라 빠뜨리기 쉬운 항목을 놓치지 않기 위한 체크리스트다.
`design-guide.md`가 "어떻게 보이는가"를 다루는 것과 짝을 이뤄, 이 파일은 "누가, 무엇을 하러 와서,
어떤 경로로 목표에 도달하는가"를 다룬다. 추측해서 채우지 않는다 — 실제 사용자 데이터(이탈 지점,
문의 내역)나 제품 담당자의 확인을 거친 내용만 적는다.

## 예시 구조

```md
## UX 설계 기준

### 타깃 사용자와 핵심 태스크
- 주 사용자층: (예: 처음 투자를 시작하는 20~30대, 금융 용어에 익숙하지 않음)
- 핵심 태스크 목록(빈도순): 1) 회원가입·로그인 2) 투자 대상 종목 확인 3) 리마인더 등록 ...
- 일회성 작업 vs 반복 작업 구분: 가입/본인인증=일회성(친절한 설명 우선), 종목 조회=반복(효율성 우선)

### 채택한 플랫폼 관례
- 웹: 일반적인 폼 기반 플로우(멀티스텝 마법사 대신 단일 페이지 스크롤 폼을 기본으로 함 — 이유: ...)
- 모바일: iOS/Android 공통 관례 우선, 플랫폼별 분기는 최소화

### 자주 쓰는 플로우 패턴
- 삭제/탈퇴처럼 되돌릴 수 없는 작업: 항상 모달 확인 + 타이핑 확인(예: "탈퇴"를 직접 입력) 요구
- 여러 단계 폼: 진행 상황(n/m)을 항상 상단에 표시, 이전 단계로 돌아가도 입력값 유지
- 에러 메시지 형식: "[무엇이 틀렸는지] + [어떻게 고치는지]" 2문장 고정 패턴

### 과거에 겪은 사용성 문제와 해결
- (날짜) 회원가입 3단계에서 이탈률 40% → 전화번호 인증을 선택 입력으로 바꾸고 15%로 감소
- (날짜) "구독 취소" 버튼을 설정 메뉴 3단계 아래 숨겨뒀다가 CS 문의 급증 → 1단계로 이동

### 접근성/포용성 관련 UX 결정 (시각 디자인이 아니라 플로우 차원)
- 색맹 사용자를 위해 상태(성공/실패)는 색만이 아니라 아이콘+텍스트로 항상 병행 표기
- 느린 네트워크 환경을 고려해 긴 리스트는 무한 스크롤 대신 페이지네이션 + 스켈레톤 로딩
```

## 작성 시 주의

- **데이터가 없으면 "미확인"으로 남긴다** — 이탈률·전환율 같은 수치는 지어내지 말고, 실측 데이터가
  없으면 "데이터 없음, 추정 불가"라고 명시한다. 추정이 필요하면 추정이라고 밝히고 근거를 남긴다.
- **`design-guide.md`와 역할을 섞지 않는다** — 색상·폰트·spacing 같은 시각 토큰은 여기 적지 않는다
  (그건 `design-guide.md`의 몫). 이 파일은 순서·구조·문구의 존재 여부·에러 처리 방식처럼 "무엇을
  보여줄지"에 집중한다.
- **그린필드 프로젝트라면** SKILL.md 본문 2~4절(목표·멘탈모델 파악, 휴리스틱 대조, 단계 수 세기)을
  먼저 거쳐 정한 결정을 그대로 이 파일의 초안으로 옮긴다 — 빈 파일로 시작하거나 방대한 표를 한 번에
  만들지 않는다.
- **모노레포에서 프론트엔드 앱이 여러 개면** 타깃 사용자·핵심 태스크가 앱마다 다를 수 있으므로
  (예: 회원용 앱 vs 관리자용 대시보드), `ux-design-guide.md`도 각 앱 루트에 따로 둔다.
